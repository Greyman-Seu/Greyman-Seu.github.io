> **具身模型的历史使命，是让身体拥有本能。**

上一篇[《既装得下，也学得会：问题空间如何决定 Scaling》](/blog/task-formulation-scaling-hypothesis)讨论了一个一般问题：什么样的问题定义，既保留足够高的能力上限，又提供可持续的学习信号。这一篇沿着同一条思路追问具身操作：**我们究竟期待一个有身体的模型学会什么？**

先把较长程的目标理解、知识组织和任务规划交给 GPT。具身模型要做的，是让一个智能体在物理世界中真正把事情做成。于是，问题的起点就不再是“模型能不能生成动作”，而是“它需要怎样理解世界，才能选择并完成一个动作”。

我的直觉是：具身模型更像一个会使用工具的动物。它不必先进行很长的语言化思考，却必须感知环境，理解自己的身体和物体的关系，知道哪些动作可能带来什么结果，并在行动中趋利避害。它要有空间感知和短时推演，能选择动作、感受反馈，在发现不对时修正、撤回或停止。

“会使用工具的动物”并不意味着具身模型只负责低级控制。会用工具本身就包含了对物体可供性的理解、对短程因果的判断、对动作经验的记忆，以及对自身、环境和他人安全的保护。

下面先整理场景和期待，再讨论模型与数据。这些仍是设计直觉，具体实现需要逐步验证。

## 先复现场景：世界、本体、其他本体

### 世界：客观存在与主观认识

**客观世界**包含各类物品、物品的空间关系和光照等环境条件。物品具有物理、化学属性；对当前的操作问题，我更关注位置、形状、软硬、摩擦和重量等。世界中的一部分物品可能不可观测，也可能与当下操作无关。

**主观世界**是本体通过观测形成的当前认识。对于某次操作，它首先需要关注与任务强相关的物品，以及会影响操作和安全的周围条件。

观测器相当于本体的“五官”。不同传感器的成像方式、畸变和观测视角，会让同一个客观世界呈现出不同的样子。模型需要克服这些差异，通过去畸变、统一观测空间等方式，尽可能消除观测器的影响，形成对物品及其空间关系的一致认识。

### 本体：身体、意图与行为

本体可以从三个方面描述：

- **身体，相对静态**：构形、尺寸、自由度、传感器和执行器，以及这个身体的特点与限制。
- **意图**：我要做什么，希望得到什么结果。这一层接近决策，也决定了当前应关注哪些信息。
- **行为，动态**：身体如何行动，行动产生了怎样的物理反馈，以及如何响应交互。

同一个意图，在不同身体上可能需要不同动作；同一个动作，也可能因为接触和受力状态不同而产生不同结果。

### 其他本体：交互与指令

其他本体包括人和其他机器人。对当前系统，首先关心它们如何给出指令、调整操作和介入执行。同时，它们的动作也可能改变当前场景。

复现一次操作，需要把这些要素放在一起：**当时的世界与身体状态、收到的指令、执行的动作，以及动作后的反馈和结果。**

## 具身操作的三项期待

### 一、操作泛化

换一个场景、物品或身体，系统仍然能够完成相同目标。我希望这种泛化同时发生在世界和本体两个方面。

**对于世界：**

- **感知偏差自适应**：适应光照、视角、遮挡和传感器偏差。
- **空间与物品泛化**：适应位置、姿态、形状和尺寸变化。
- **物理属性泛化**：适应软硬、摩擦、重量等变化，并据此调整动作。

这里需要区分两类变化：光照变化可能只需要消除其对判断的干扰，重量变化却需要实际改变施力。感知应当屏蔽无关干扰，同时保留会改变操作结果的信息。

**对于本体：**

- **本体泛化**：适应身体构形、工具和能力的变化。
- **反馈响应泛化**：面对不同阻力、滑动或外界扰动，能够根据反馈调整行为。
- **技能泛化**：已有操作技能可以迁移到新物品、新场景，也可以组合成新的操作。

关于本体泛化，我的想法发生过变化。以前我倾向于让模型专注于一个固定本体；后来想到，人进入虚拟现实、使用一个并非自己的身体时，也可能较快适应。这让我愿意重新考虑本体泛化：如果操作能力能适应新的身体，就更有利于模型的复制与传播。这是一个值得验证的直觉。

### 二、操作安全

操作至少应守住两条边界：不能损坏自身，不能对其他物品造成任务之外的破坏；涉及人或其他本体时，也要保护它们。

切割、拆卸等任务本身允许改变物品，因此安全边界需要结合目标来定义。模型要理解哪些变化被允许，哪些后果不可接受。

我可以接受早期模型的操作效果差一些，但不能接受它因为能力不足而随意造成损伤。早期可以从受限的任务、速度和力度开始，让执行层的约束与停止机制共同守住边界。

对应到能力上，模型需要察觉自己做错了，在异常时停止继续推进，并判断应该修正、恢复还是求助。失败之后能否安全地继续，是操作能力的一部分。

### 三、交互可控性

我暂时用“交互可控性”概括第三项期待：**理解当前任务，进行短时判断，并支持交互、查询和细致控制。**

上层给出的不能只有一个固定动作标签。操作过程中，还应该可以调整目标、速度、力度和停止条件。例如：

```text
目标：拿起杯子
约束：保持竖直，轻一点
执行中调整：慢一点，先停一下，换一个抓取位置
状态查询：抓稳了吗？为什么停下？
反馈：正在滑动，需要重新调整
```

这需要上下文能力。模型应记得当前目标、刚才做过什么、收到什么反馈，以及哪些约束仍然有效。必要时通过多轮交互澄清指令，并支持更细致的查询。

这里需要的智能主要围绕当前操作：理解局部状态，判断下一步，预估短时间内的结果。较长程的思考仍可以交给上层 Agent。

## 在三个期待下考虑模型能力

### 执行效率与早期效果

末端执行的响应效率必须足够高。对于灵巧手，我的初步设想是局部控制可能需要达到 100 Hz 或更高；具体频率要结合任务和硬件验证，也需要区分操作模型更新与底层控制的频率。

效果可以逐步提高，但安全边界需要从一开始就存在。早期模型可以完成得慢一些、需要更多调整或求助，再通过反馈积累稳定操作的能力。

### 动作粒度与技能

最基础的动作可以先考虑 delta，也就是位置、姿态或关节量的增量操作。

但一次增量还不足以描述完整技能。技能需要把连续动作、反馈和完成条件组织起来。例如，“抓住杯子”需要在接近、接触和施力过程中持续判断，而不只是执行一次位移。

因此，底层动作要足够细，才能精确控制；上层技能要能够组合和迁移，才能支持操作泛化。两者都需要接受安全约束。

### 上下文、感知与恢复

这几项能力可以回到三个期待来检查：

| 期待       | 对应能力                                                   |
| ---------- | ---------------------------------------------------------- |
| 操作泛化   | 抑制无关感知偏差，适应身体与物品变化，根据交互反馈调整技能 |
| 操作安全   | 发现异常与错误，停止危险动作，并选择安全的恢复方式         |
| 交互可控性 | 保留任务上下文，理解细致指令，支持状态查询和执行中的调整   |

上下文可以包含近期状态、动作和反馈，也可以带入过去的操作经验。具体采用多轮输入、较长上下文还是独立记忆，需要根据系统实现验证。

## 用 Agent 闭环逐步学会稳定操作

在这些期待下，我希望系统能够通过 Agent 范式，像“左脚、右脚”交替前进一样迭代：

```text
理解目标与当前场景
→ 执行一段操作
→ 观察物理反馈
→ 判断结果与偏差
→ 调整、恢复或求助
→ 继续执行并记录经验
```

上层 Agent 调整目标和步骤，具身模型根据当前身体与反馈展开动作。一次操作中的调整可以先发生在上下文里；要把经验变成稳定能力，还需要记录、学习和后续验证。

## 一个现实条件：数据能否收集

问题空间还必须对应可收集的数据。对于前面的世界、本体和其他本体，我们能记录哪些状态？动作与反馈能否对应起来？成功、失败和恢复过程能否被保留？

除了动作轨迹，我尤其关心当时的观测、身体状态、交互指令、物理反馈和任务结果。它们决定了模型能否看见操作为什么成功、为什么失败，以及下一次应该如何调整。

这些条件共同决定系统的起点：希望模型泛化的变化，需要在数据中有所体现；希望守住的安全边界，需要在执行中能够检查；希望实现的细致交互，需要有相应的上下文与反馈接口。

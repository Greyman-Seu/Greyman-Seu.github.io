> **具身模型的任务，不是把一句话翻译成一串动作，而是让动作在真实世界里成立。**

上一篇[《既装得下，也学得会：问题空间如何决定 Scaling》](/blog/task-formulation-scaling-hypothesis)讨论了一个一般问题：什么样的问题定义，既保留足够高的能力上限，又提供可持续的学习信号。这一篇沿着同一条思路追问具身操作：**我们究竟期待一个有身体的模型学会什么？**

先把较长程的目标理解、知识组织和任务规划交给 GPT。具身模型要做的，是让一个智能体在物理世界中真正把事情做成。于是，问题的起点就不再是“模型能不能生成动作”，而是“它需要怎样理解世界，才能选择并完成一个动作”。

我的直觉是：具身模型更像一个会使用工具的动物。它不必先进行很长的语言化思考，却必须感知环境，理解自己的身体和物体的关系，知道哪些动作可能带来什么结果，并在行动中趋利避害。它要有空间感知和短时推演，能选择动作、感受反馈，在发现不对时修正、撤回或停止。

“会使用工具的动物”并不意味着具身模型只负责低级控制。会用工具本身就包含了对物体可供性的理解、对短程因果的判断、对动作经验的记忆，以及对自身、环境和他人安全的保护。

## 具身操作的三项期待

### 操作泛化

换一个物体、位置、视角、光照、重量或摩擦条件，模型仍然应该知道怎样完成同一个目标。它要泛化的不是某条固定轨迹，而是“在这些变化下，哪些关系仍然成立”。

因此，操作泛化至少包括几个方向：

- **指令泛化**：同一个目标可以用不同说法表达，也可能是不完整、模糊或需要追问的指令；
- **视觉泛化**：视角、遮挡、背景、光照和传感器变化不应直接破坏操作；
- **物品泛化**：从一个杯子迁移到另一个杯子，从熟悉类别迁移到未见实例，并适应形状、材质、重量的变化；
- **位置与空间泛化**：目标出现在不同位置、姿态、距离和布局中，动作仍能重新组织；
- **操作泛化**：已有技能可以组合成新的动作顺序，也能在工具和任务变化时调整；
- **物理泛化**：面对不同摩擦、软硬、接触和外力，模型能根据反馈改变速度、姿态和力度；
- **本体适应**：跨机器人迁移可以不是第一优先级，但模型必须知道当前身体、末端工具、负载和标定误差。

这几种泛化不是同一件事。看到一个新物体，和知道如何对它施力，中间还隔着物理理解；在新位置看见目标，和在新位置成功抓取，也不是同一个能力。

### 可被细致调度

上层不能只给出一句“拿起杯子”。如果具身模型只接受固定动作标签，它很难表达风格、约束、经验和临时调整。

一个可调度的操作目标，至少应该包含：

```text
目标：拿起杯子
前置条件：杯子可见，手臂可达
子动作：定位 → 接近 → 调整姿态 → 接触 → 施力 → 抬起
风格：轻柔、稳定、低速
约束：避免碰撞，限制握力和速度
成功标准：杯子离开桌面并保持稳定
失败处理：重新定位、换抓取点或请求重规划
```

这里的接口不是为了把每个关节角度都交给上层，而是要让上层能够调整任务真正关心的变量：目标、子任务、风格、风险预算、注意力、记忆和停止条件。

具身模型则要返回比“成功/失败”更丰富的状态：当前进度、身体状态、动作置信度、接触和受力情况、失败原因、可选替代方案，以及它是否需要人或上层 Agent 介入。

### 操作安全

安全不是完成操作以后再外挂的一层规则。模型在选择动作时，就应该把人的存在、物体的脆弱程度、身体的限制和动作的可逆性纳入判断。

安全至少有三种尺度：

- 保护自身，避免碰撞、失稳、过力和超出身体限制；
- 保护环境，避免损坏物品和造成不可逆的变化；
- 保护人，保持合适的距离和力度，识别人的介入并响应停止信号。

但安全也不能全部交给模型的判断。急停、最大力、速度、温度和工作空间等边界，仍然需要独立的硬约束。模型应该负责预测风险和表达不确定性，系统则负责在模型犯错时兜底。

## 操作模型应该理解什么

具身模型要建立的不是一个完整的宇宙模型，而是一个足以支持行动的内部世界。至少需要同时处理四层内容：

1. **本体世界**：我在哪里，身体能到哪里，是否接触、抓住、受力、失稳或异常；
2. **物理世界**：物体、表面、空间、障碍、重量、材质、摩擦和运动；
3. **行动世界**：什么可以抓、推、拉、插入或打开，动作会带来什么结果；
4. **其他智能体**：人的意图、注意力、介入和协作关系。

主观世界可以理解为模型对这四层内容的当前判断。真实世界通过传感器进入模型，模型据此选择动作，动作再改变世界并产生新的反馈：

```text
世界 → 传感器 → 当前判断 → 动作 → 新反馈
```

其中第三层“行动世界”最能区分具身模型和普通视觉模型。看见杯子只是识别，知道从哪里抓、施多大力、抬起后怎样保持稳定，才是操作意义上的理解。物体不只是类别，还应该带有可供性：在当前身体和当前状态下，它能被怎样改变。

## 重新定义操作的输出

如果把操作问题写成一次性的函数，可能会得到：

$$
 a=f(o,g)
$$

其中 $o$ 是观察，$g$ 是目标，$a$ 是动作。但真实操作不是一次映射。动作会改变环境，身体也会产生新的感觉；同一个动作在不同接触状态下可能产生完全不同的结果。

更接近实际的形式是一个闭环：

$$
 (s_{t+1},r_t,e_t)=F(s_t,a_t,o_{t+1})
$$

这里的 $s_t$ 包含环境和本体状态，$a_t$ 是当前动作，$o_{t+1}$ 是新的观测，$r_t$ 表示任务结果，$e_t$ 表示异常或不确定性。模型要学的不是一条脱离反馈的轨迹，而是怎样根据状态选择动作，并从后果中更新判断。

因此，操作模型的目标空间最好同时包含：

- 状态：身体、物体和环境当前是什么样；
- 动作：当前可以采取什么技能或子动作；
- 结果：动作是否改变了目标状态；
- 反馈：视觉、触觉、力觉和本体感觉提供了什么证据；
- 失败：为什么没有成功，下一步应该重试、替代、撤回还是求助。

这比单纯预测下一帧更接近操作的真实期待。视频预测可以学到外观和运动先验，却不一定需要区分抓取是否稳定、接触力是否安全，或者某个动作能否真正控制结果。要让模型学习可操作的世界，训练中需要出现动作条件、状态变化、接触反馈和任务结果之间的联系。

## 记忆应该怎样进入操作

一次成功的操作不应该只在当下结束。模型需要能够保存动作经验，并在未来作为前序输入使用。

动作记忆可以写成：

```text
场景：木桌上的玻璃杯
目标：拿起杯子
经验：从杯身中部接近，低速闭合，保持竖直
参数：较小握力，避免碰撞杯口
结果：成功
限制：杯子湿滑时需要进一步降低速度
```

失败也应该成为记忆：从杯口抓取为什么容易滑脱，在什么姿态下会碰撞，哪些条件下需要换一个抓取点。

这些记忆不是可以无条件复制的程序。它们更像先验，必须先和当前视觉、触觉、力觉及身体状态比较，再决定是否采用。记忆系统可以负责检索相关经验，具身模型负责验证这次是否适用，并在结果出来后更新经验。

## 问题空间的解决思路

从第一性原理出发，具身操作的问题空间应该同时满足三个条件。

**第一，能够表达真实期待。** 如果输出只包含离散动作类别，就很难表达力度、接触、连续姿态、失败和安全边界；如果只预测图像，就很难表达动作是否可控。问题空间必须保留那些会改变操作结果的差异。

**第二，能够让监督抵达关键能力。** 训练目标不必全部是人工标注，但数据必须让模型看到动作、身体、环境和结果之间的关系。视觉、触觉、力觉、轨迹、语言指令和任务成败可以共同组成监督。密集的像素损失不等于密集的操作监督；关键是它是否约束了模型真正关心的接触和控制变量。

**第三，能够支持组合和复用。** 模型不应该为每个物体和每个位置各记住一条轨迹，而要把可复用的部分组织成技能、关系和变化规则。定位、接近、抓取、移动和放置可以组成新的任务；同一套接触规律也应该跨物体和场景复用。

可以把这条思路压缩成一个训练闭环：

```text
期待：希望模型安全地完成哪些操作
→ 问题空间：状态、动作、结果和反馈如何表示
→ 数据：哪些变化和接触关系需要被覆盖
→ 监督：动作后果和任务成败如何被看见
→ 模型：规律能否跨场景复用
→ 真实操作：是否真的更稳、更广、更安全
```

## 具身操作的最小闭环

第一版模型不必先追求完整的人类智慧，也不必把所有规划都塞进端侧。它至少应该形成这样的闭环：

```text
感知环境与身体
→ 理解物体和可供性
→ 选择或展开技能
→ 以合适的风格和约束执行
→ 读取视觉、触觉、力觉反馈
→ 判断成功、失败或未知
→ 修正、撤回、记忆或求助
```

在这个闭环里，GPT 可以提供目标、长期记忆和高层计划，但具身模型必须拥有自己的局部状态、动作记忆和安全边界。上层调度的是可执行技能，具身模型展开技能并根据物理反馈完成它。

> **具身模型不是把语言变成动作的末端插件，而是一个能在本体、物理和行动世界之间建立闭环的操作模型。它的上限来自操作泛化，它的可用性来自可被调度，它的底线来自安全。**

[《闪念决策》](/blog/embodied-operation-flash-decision)讨论了我对快速具身判断的期待。这一篇把构想展开为完整的研究方案：先说明 Sys1 要承担什么，再讨论 Jev 提供的参考、模型与数值接口，最后收敛到可检验的最小方法、数据和实验。

以 Jev 的类型化判断范式为参考，研究一个连接 Sys2 与 Sys0 的通用局部决策模型：输入丰富、可变的多模态上下文，输出紧凑的判断与末端轨迹，并在真实执行后持续纠错。

本文先定义 Sys1 应承担的认知与控制职责，再梳理 Jev、开放决策模型和具身策略的相关研究，提出“共享多模态骨干＋问题条件化解码器＋类型化读出”的完整设计。在资源有限的第一阶段，将任务收敛为**低频 EEF 轨迹与跨场景分类判断的联合学习**，以语义抓取作为闭环载体。最小实验需要证明的不是接口能输出数字，而是分类中保留的知识能够改变动作，并从训练域迁移到未见的真机物体和场景。目标平台为非夕机械臂、夹爪与多目 RealSense RGB；部署不使用深度通道。

<Aside type="note" title="研究状态">

本文是一份研究设计。已有数值原型仅在合成输入上检查过；RGB 模型训练、仿真闭环、非夕真机零样本和 Astra 对照均尚未完成。下文将公开证据、设计建议与待验证假设分开陈述。

</Aside>

## 01 · Sys1 的期待：把理解落实为眼前的行动

设想上层说：“拿起左边的杯子，避开旁边的碗；刚才没有抓稳，这次换一侧接近。”执行这一要求不只需要识别“杯子”，也要判断“左边”相对于什么、之前哪里失败、当前是否仍有操作空间，以及下一段末端运动应如何改变。这些判断比长期任务规划更局部，却比跟踪一个固定轨迹更有认知含量。

我们把这层能力称为 **Sys1**。它接住 Sys2 整理的意图与背景，在当前观测和交互记忆下形成局部计划，再把计划交给 Sys0 执行。它可以输入语言、图像、结构化数值和反馈，但不需要通过语言解释自己；输出是程序可直接使用的索引、状态、参数和短段 EEF 轨迹。这与《闪念决策》提出的丰富上下文、紧凑输出和及时调整方向一致。[[1]](/blog/embodied-operation-flash-decision)

### 预期保留的能力

第一是**听得懂新要求**：同一画面换目标、接近方向或禁区，动作应正确改变。第二是**会使用已有证据**：参考图、历史失败和当前状态能共同决定下一步。第三是**知道何时不能继续**：观测不足、目标已变、执行未到位时，能观察、恢复或交回 Sys2。第四是**跨场景迁移**：换物体、布局和相机后，仍尽量复用语义与局部控制知识。

这些能力不要求 Sys1 承担所有长程推理，也不要求输出越多越好。理想的 Sys1 是“有足够理解能力的短程决策者”。其低频是相对于身体控制而言；约 10 Hz 是后续响应目标，最初应先验证正确性与闭环泛化。

<Aside type="tip" title="研究问题">

能否把预训练模型的上下文理解，转移到不生成语言的判断与 EEF 输出接口，并通过有限的具身训练获得真实可用的零样本局部操作能力？

</Aside>

## 02 · Jev 是 Sys1 的参考方案，而不是现成的机器人模型

Jev 的重要启发是将“理解输入”和“生成文字”分开：请求给出状态与有类型的问题，模型返回选择、评分或真假判断，程序据此行动。官方接口强调直接返回类型化结果，以及多个问题的并行求值。这使“读很多背景、只回答少量关键问题”成为明确的模型接口。[[2]](https://docs.typesafe.ai/introduction)

<Aside type="note" title="同一个操作场景，可以问不同类型的问题">

**选哪个对象？** → 动态对象集合中的索引<br />**刚才是否真正抓住？** → 抓稳／夹空／未知<br />**下一段末端应去哪？** → 带时间的位姿与夹爪数组

</Aside>

前两类很接近 Jev 的原语，第三类则是我们要补上的连续空间接口。这里的“Jev 式”指**问题条件化、非语言、类型化读出**，不限定必须采用 Jev 服务、离散分箱或某一种训练算法。训练一个有类似接口的开放模型，也不等于复现了 TypeSafe 的私有架构与 RLCD 配方。

<div class="my-6 max-w-full overflow-x-auto" role="region" aria-label="值得借鉴对照表" tabIndex={0}>

| 值得借鉴             | 迁移到 Sys1 的设计                                     | 不能直接推导                                     |
| -------------------- | ------------------------------------------------------ | ------------------------------------------------ |
| 输出由问题类型约束   | Choice、状态与 EEF 轨迹都有固定语义和合法域            | 类型合法不保证目标、坐标或动作正确               |
| 少量结果、并行读出   | 一个前向产生多个时间槽，减少文字生成开销               | 输入编码与长上下文成本仍在，不能据此保证 10 Hz   |
| 候选与问题随请求变化 | 对象、技能、约束可用输入描述，避免固定类别封闭全部语义 | 新语义可组合，不代表未知传感器与执行原语自动可用 |
| 概率服务于决策       | 区分执行、观察与升级，按验证集设阈值                   | 模型的高置信度不自动等于真实抓取成功概率         |

</div>

**需要主动偏离 Jev 的一点：**官方独立问题求值适合独立判断，而一条轨迹的位置、姿态、夹爪和时间彼此相关。因此本文让同一计划中的槽位联合交互；不能把许多独立坐标判断拼起来，就称为一条联合可行的轨迹。公开图像／Box 能力说明输入与输出原语可以扩展，但没有证明从像素到三维抓取的能力。[[3]](https://docs.typesafe.ai/images)[[4]](https://docs.typesafe.ai/primitives/box)

### 3.2 数值输出：能读出一个数，与能形成一条路径不同

NumericJev／JevNext 把数值范围递归细分为离散选择，避免依赖自由文本数字格式；它可以控制读出分辨率，但需要顺序决策轮次，其数值任务结果不能外推到整段运动。[[19]](https://arxiv.org/abs/2609.28587)[[20]](https://github.com/Bring-AI/JevNext/blob/a83d87e9ce5d3d83dc6148c765a4d76196711aad/README.md)阈值 CDF、分箱与连续回归也都是可行的编码工具。对于机器人，必须进一步解决单位、范围、旋转、时间、多个合法解和路径联合一致性。

因此本文将“数值表示”和“共享决策范式”分开：连续 head 是最小实验的工程选择；离散 head 是有价值的同条件对照。最终要比较的是几何有效性、闭环成功和时延，而非仅比较格式合法率。

### 3.5 Astra 提供的是目标参照，而不是可直接抄用的训练配方

第三方 Astranomy 研究区分直接策略与带上下文／工具的 agent，并比较是否给出相机和夹爪几何；不同配置都存在可行结果，但显式几何对直接策略的影响较大。[[47]](https://research.nvidia.com/labs/srl/projects/astranomy/index.html)另一个 RoboDojo pilot 明确使用 RGB、本体与静态标定，没有输入深度。[[48]](https://cookiegg.github.io/llm-as-policies/)这些说明应比较多种几何条件，不能假设 Astra 一律有标定或一律无标定。

OpenAI 发布资料没有披露足以重建本项目所需的抓取训练／标定配方；第三方使用 OpenAI 模型的机器人系统，应按作者的 harness 解读。[[49]](https://openai.com/index/gpt-6-astra/)我们真正借鉴的是“读取丰富上下文—给出局部动作—根据结果纠正”的工作方式。非语言学生能保留多少这种能力，需要在相同观测和执行条件下测量。

<Aside type="tip" title="由 related work 得到的研究空缺">

已有工作分别展示了快速判断、连续动作与语言控制。我们需要验证的是：共享同一个非语言接口的通用判断与 EEF 学习，能否让任务理解和交互记忆在真实未见场景中持续影响动作。

</Aside>

## 04 · 终局设计：容纳哪些任务，输入输出是什么

<Aside type="note" title="一个完整例子：输出 bbox ID，可以，而且正是一个完整的 Choice 任务">

**输入：**当前 front 视角中的三个杯子，归一化 `xyxy` 分别为 `b17=[0.10,0.45,0.30,0.85]`、`b23=[0.60,0.45,0.80,0.85]`、`b31=[0.15,0.15,0.28,0.40]`；指令为“抓左边杯子，不要后面的”，问题为“目标是哪一个？”。“左”约定为 front 图像的横向方向。

**有足够证据时：**若 RGB／空间上下文还确认 b31 是后排杯子，候选表为 `[b17,b23,b31,unknown]`，模型可输出 `choice_index=0`；程序映射为 `target_bbox_id=b17`。模型不用生成“我选左边杯子”这句话。

**只有裸 bbox 时：**可以按横坐标判断画面里的左右，但不能普遍把画面靠上、框更小解释为物理上的“后面”。若缺少前后关系且存在歧义，应选 `unknown`／请求观察；如果输入本来就给了可靠的前后关系，bbox＋这些关系也可以完成选择，不必额外强制输入 RGB。

**多目与动作：**bbox ID 应绑定 `request_version、view_id、frame_id`。同一个杯子在两目中的框只有经跨视角关联，才能映射到共同的 `object_id`；不能默认两目同编号就是同物体。选择题输出这个引用即可；若本次问题是“怎样抓”，还需要输出 EEF 轨迹、夹爪与状态。两者可以共享上下文联合读出，bbox ID 本身不是三维抓取点。

</Aside>

新的物体、任务描述和候选集合可以通过上下文组合接入；新的物理能力则仍需数据和执行器支持。比如已有“位姿＋夹爪”接口可以服务许多抓放任务，但不能只修改 schema 就获得灵巧手指尖控制或力觉。

### 输入契约：内容灵活，语义可追溯

每次请求由 `ContextPack＋QuestionSet＋OutputSchema` 组成。ContextPack 按块容纳任务与约束、当前图像、参考图、身体状态、过去的状态—动作—结果、长期经验和 Sys2 分析。QuestionSet 说明本次要解决哪些判断；OutputSchema 限定输出类型、坐标系、单位、时间范围与可用末端。

每个块至少有 `type、role、timestamp、source`；图像另有 view_id，空间量另有 frame 与单位。历史动作区分“请求执行”和“实际执行”。上层分析被标记为假设，不能覆盖传感器事实。缺少图像时可以处理纯文本或状态分类，但缺少关键空间证据时不应被强迫输出唯一轨迹。

### 输出契约：共享原语，组合任务

<div class="my-6 max-w-full overflow-x-auto" role="region" aria-label="输出原语对照表" tabIndex={0}>

| 输出原语             | 定义                                    | 可表达的任务                                       |
| -------------------- | --------------------------------------- | -------------------------------------------------- |
| Choice / Reference   | 在本次给定候选中返回索引与分布          | 对象、方式、阶段、失败类型、证据引用               |
| Bool / Defined score | 二元判断或有明确标准的评分              | 完成、可执行、需要观察；评分不是未经验证的成功概率 |
| Scalar / Vector      | 有单位、范围和有效性标记的数值          | 时长、夹爪宽度、空间目标、约束参数                 |
| Pose trajectory      | E 个末端、H 个时刻的位置／旋转／夹爪    | 单臂、多臂、工具与局部路径                         |
| Lifecycle            | execute / observe / complete / escalate | 执行、补观测、结束、交回 Sys2；也可由 Choice 实现  |

</div>

输出中的 JSON 字段名由程序序列化，不是模型逐 token 写 JSON。plan_id、request_version、观测与启动时间由框架传递。引用对象仅在请求里有相应候选表时返回；没有检测器或对象列表时，模型仍可从 RGB 直接输出 EEF，不能暗中依赖不存在的对象 ID。

## 05 · 数值如何表示：先把物理语义定清，再选择编码

“输出 float”只是程序类型；机器人需要的是“哪一个工具点，在什么坐标系，什么时候，到什么位置和姿态”。我们统一输出末端任务空间，减少对关节数量和连杆长度的直接依赖，同时保留本体描述和可达性约束。

```text
Y = {status, phase, target_ref?, π[K], trajectory[K,E,H], valid_mask}
trajectory[k,e,h] = {p_xyz [m], R [rotation], gripper, time_s}
网络预测数值与选择；框架补充 request_version、TCP、frame、observed_at、plan_start。
```

### 位置、旋转、时间和夹爪

<div class="my-6 max-w-full overflow-x-auto" role="region" aria-label="量对照表" tabIndex={0}>

| 量     | 最小方案                                                   | 终局方案与注意点                                                                                                          |
| ------ | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 位置   | robot_base 中指定 TCP 的绝对 xyz，米；按训练域范围归一化   | 比较绝对、当前 EEF 相对和任务坐标表示。归一化范围仅由训练数据／预定义能力域确定，目标真机测试不重新估计                   |
| 旋转   | 明确的俯抓姿态 R_down，加 yaw 的 cos/sin；R = R_z(ψ)R_down | 用 6D rotation 经正交化得到 SO(3)，部署转换为固定顺序的单位四元数；退化向量要检查[[50]](https://arxiv.org/abs/1812.07035) |
| 时间   | H=8；相对 plan_start 的 [0.1,…,0.8] s，由 schema 固定      | 可学正值 Δt 并累加，保持严格递增；预测时刻与执行起点分开                                                                  |
| 夹爪   | 连续宽度或明确开／闭事件；闭合与释放有专门标签             | 实际行程、指尖几何、工具点随设备定义；不把训练夹爪归一化值直接当另一台的毫米数                                            |

</div>

TCP 与法兰转换由确定性代码完成：`T_base_flange = T_base_tcp · inverse(T_flange_tcp)`。这个身体接口即使在不输入相机标定的条件下也必须定义。位置相对化同样不能消除未知相机轴与动作轴的关系。

### 连续回归、分箱和数值树如何选择

<div class="my-6 max-w-full overflow-x-auto" role="region" aria-label="表示对照表" tabIndex={0}>

| 表示             | 优势与代价                                             | 本文选择                                                      |
| ---------------- | ------------------------------------------------------ | ------------------------------------------------------------- |
| C0：连续回归     | 并行、输出紧凑、无需分箱；需处理尺度、旋转、多解和边界 | **最小主线**。位置 Huber／L1，yaw 周期误差；低成本建立强对照  |
| D0：每标量分箱   | 可用分类损失，方便离散概率；分辨率随物理跨度变化       | 第二阶段同数据、同骨干、同 decoder 消融，不与不同训练策略混比 |
| 范围递归／数值树 | 逐步细化精度；需多轮推断，错误分支会传播               | 数值理解基线，不默认适合作为每个 EEF 坐标的实时读出           |
| Flow／diffusion  | 可建模复杂多解动作分布；训练与推理更复杂               | 当单模式或小 K 明显不足后再引入，不是第一轮必要条件           |

</div>

<Aside type="note" title="分辨率不等于准确率">

若长度 L 的范围包含 B 个均匀网格点，间距为 Δ=L/(B−1)，最近邻舍入误差上限为 Δ/2。0.6 m 范围的 256 点间距约 2.35 mm，1024 点约 0.59 mm；这只是表示误差，不含视觉、标定、模型和执行误差。连续 float 也不意味着具有毫米级预测精度。

</Aside>

抓取可以有多个合法姿态，绕障可以有多条路径。第一轮在限定俯抓场景使用 K=1；出现多解平均问题后，扩展 K=3 个整段轨迹 mode。训练按整条路径匹配，推理选择一条完整 mode，禁止逐点选最优或对左右绕行取均值。best-of-K 回归加模式分类不是已校准的联合概率密度；若需要密度意义，再定义相应似然。

连续 head 是数值实现，Jev 式接口是组织原则，两者不冲突。没有必要为了“像 Jev”把所有坐标都变成分类，也不能因为选择回归就放弃分类与动作共享上下文。

## 06 · 模型如何设计：共享理解层，区分必要的输出语义

终局结构采用可访问隐藏状态的预训练 VLM，沿用原图像处理器与 tokenizer。文本、图像和历史先进入统一上下文；精确本体／几何数值可以经小型数值适配器追加到记忆中。问题、schema 与候选描述也在本次骨干输入中编码；其表征再结合类型、末端与时间索引生成查询槽，从这份记忆读取所需判断或轨迹。数值适配器保留单位和坐标语义，不承担从未知相机到机器人坐标的隐式确定性变换。

**“统一 head”不必理解为所有量使用同一条线性层。**合理的共享发生在上下文表征和问题解码器；末端位姿与动态候选具有不同输出空间，使用小型类型专用读出是必要的。若用一套互不相关的模型分别做分类和控制，就无法检验共享认知是否迁移到动作；若把所有东西硬塞进相同固定类别，又会限制任务扩展。

### 具体读出

Choice 查询得到向量 z_q，与当前候选描述的表征 c_i 进行条件化打分：`p(i|C,q)=softmax_i f(z_q,c_i)`，padding 候选被屏蔽。候选可以是文字、图像区域或对象记录，语义由输入提供，不靠固定标签 ID。轨迹查询由末端索引、时间索引和字段类型构成；一次前向并行产生 H 个目标，相关槽位在解码器中交互，不需要把先前真实动作当未来输入进行 teacher forcing。

完整模型可以在一个请求里回答多个问题，但不相关分类题之间不必允许任意信息串流。第一版每条样本只问一个任务，或者输出一组相关的抓取状态与轨迹；终局扩展到多问题时，显式设置 query 分组 mask，避免一个问题的答案成为另一个问题的隐式泄漏。

### 长上下文与推理预算

上下文策略优先保存最近完整状态转移、关键失败、当前有效目标和必要参考。旧记录可由 Sys2 摘要，但摘要不是新增观测。先验收 4–8k，再扩展 32k／64k；长序列容量不等于能使用遥远证据。可复用不变前缀，但修改旧目标／历史时应使相关缓存失效。

单次前向 head 可能无法继承 Astra 的多轮推理与工具使用。若后续需要，允许固定次数的 latent refinement 或明确升级 Sys2，但应分别报告推理预算和独立成功率；不能在线让 Astra 算完最终轨迹，再把学生复用的成绩记为独立 Sys1 能力。

## 07 · 最小验证单元：EEF 轨迹＋混合分类任务是否足够？

**可以用这两类输出启动研究，而且这是推荐的第一步。**它们分别承载“应该怎样动”和“根据上下文作什么判断”，足以构建一个小而完整的 Sys1 原型。但这只是输出类型的最小化；如果数据只有无语义的轨迹回归和彼此无关的分类，模型可能把两件事各自学会，却没有学会用理解指导行动。

<Aside type="tip" title="最小单元的准确表述">

一个共享 VLM＋query decoder，联合学习 EEF 短轨迹和 Choice／Bool；分类数据同时含通用判断与操作相关判断，用一个可观察、可纠错的抓取闭环检验知识是否进入动作。

</Aside>

### 两类输出，三类数据

<div class="my-6 max-w-full overflow-x-auto" role="region" aria-label="数据对照表" tabIndex={0}>

| 数据            | 输入与标签                                                                       | 作用                                             | 单独不足在哪里                                                   |
| --------------- | -------------------------------------------------------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------- |
| T：EEF 轨迹     | RGB＋要求＋状态／历史 → 位置、受约束姿态、夹爪与时间；附闭环必需的阶段／状态标签 | 建立具身输出和短程控制能力                       | 可能记住场景到动作的对应，忽略问题与历史                         |
| B：操作相关分类 | 同一操作证据 → 抓谁、哪条约束有效、是否到位、夹空还是抓住、下一阶段              | 将指代、进展和恢复判断与动作场景连接             | 答对问题仍不保证执行正确，必须与轨迹配对验证                     |
| G：其他场景分类 | 阅读与证据判断、图文指代、空间关系、任务路由等 → 动态 Choice／Bool               | 扩大语义覆盖、保留通用条件理解，避免只会抓取模板 | 新闻主题等无关类别不会教会三维抓取；只保分类分数不是动作泛化证据 |

</div>

T 及所有动作基线都保留执行所必需的阶段、终止和观察状态监督；B 是额外的目标指代、约束、证据与恢复判断配对。不能通过删掉 T 的基础闭环能力，制造混合分类的优势。分类不必额外引入很多输出头。抓取的 execute／observe／complete／escalate、阶段和失败类型均可通过同一个 Choice 接口表达。因此最小模型仍是“分类＋EEF”两类读出；它已经可以形成完整闭环，而不是只能离线拟合未来坐标。

### 保留什么，暂不做什么

载体限定为单臂、平行夹爪、桌面不透明刚体的俯抓。输入保留多目 RGB、文本要求、本体与少量交互历史；姿态保留俯抓 yaw，输出包含夹爪与阶段。首先验证目标选择、临时改口和一次失败后的恢复。复杂力控、双臂、灵巧手、长任务、任意姿态与超长上下文后置。

第一轮仍以真机零样本为最终检验：仅在仿真跑通不算完成最小研究。缩小的是技能和物理复杂度，而不是取消语义、视觉或跨域迁移。单纯“给定三维目标点→EEF 插值”可以作为工程检查，但没有回答本研究问题。

### 三个可以被实验否定的假设

1. **H1 · 接口假设：**给同一基座增加非语言读出后，仍能正确使用目标、约束和操作历史。若原生接口会、head 不会，说明接口学习不足。
2. **H2 · 混合假设：**T＋B＋G 比仅 T 更能响应未见要求，并保持通用分类能力。若仅分类分数提高、动作不变，说明知识没有跨到轨迹。
3. **H3 · 迁移假设：**上述模型经仿真／公开数据训练后，在冻结模型与提示的条件下能完成未见真机抓取。若仿真好、真机差，应定位到视觉、空间映射或执行，而不是宣布范式成立。

## 08 · Method：怎样把这个最小单元训练成局部策略

### 8.1 模型实例与推理流程

主候选沿用具有原生图文入口的 Qwen3.5-9B，4B 用于成本对照；确切 checkpoint 与依赖在正式实现时固定。选它是因为可访问和训练隐藏状态，不意味着它已有 Astra 级能力。[[51]](https://huggingface.co/Qwen/Qwen3.5-9B)query decoder 起点为 2 层、256 维、8 个 attention heads，K=1、H=8，Choice 与数值读出共享 decoder。

**每次局部决策**

1. 读取最新有效目标、2–3 目 RGB、实测 TCP／夹爪及最近 2–4 轮状态转移。
2. 按角色、视角、时刻构造 context；根据请求产生阶段／状态与 EEF 查询。
3. 骨干前向一次，decoder 并行读出判断和 0.8 s 的末端目标序列。
4. 若需要观察或升级，返回类型化状态；若可执行，检查版本、时效、范围、连续性、IK 和碰撞。
5. Sys0 执行已接受计划的短前缀，返回真实运动与夹爪状态，重新观察。

Sys2 首轮可以由固定任务包替代；先测清楚 Sys1，再接入在线上层。目标变更使旧计划失效。Sys0 固定，不参与本研究的联合训练；它可以插值和追踪，但不代替模型选择正确物体或重新理解指令。

### 8.2 如何让分类真的帮助动作

关键不在于把两种 loss 相加，而在于**同一证据的跨任务配对**。对同一组图像和历史，分别构造“选目标”“判断是否到位”“预测下一段 EEF”的问题；答案在语义上必须一致。再改变目标或有效约束，重新求解正确轨迹，得到反事实配对。训练问题和答案分离，不能把正确分类标签直接作为轨迹样本的输入。

<Aside type="note" title="贯穿样例：杯子旁边有碗">

问题 A：“目标是哪个？” → 杯子引用。<br />问题 B：“直线接近是否违反禁区？” → 是／否／证据不足。<br />问题 C：“输出下一段 EEF。” → 满足条件的轨迹。<br />将要求改为“抓碗”或“从另一侧接近”后，重新标注 A/B/C。训练及测试均检查分类正确性和轨迹约束满足率；不只检查输出有没有变化。

</Aside>

历史训练也采用可辨别的成对条件：当前观测相近，但先前已执行动作、物体响应或失败类型不同，下一步可能不同。无关旧文字不应改变动作；缺少关键证据时允许 observe。这样可防止模型仅把“失败”这个词当作固定恢复动作触发器。

### 8.3 损失与共享梯度

```text
L = λT · L_action + λB · L_bridge-choice + λG · L_general-choice + λK · L_anchor
L_action = L_EEF + λcontrol · CE(phase / lifecycle)
L_EEF = masked mean [Huber(p) + λR · rotation_error + λg · gripper_error]
L_Choice = CE；多个合法答案时为 −log Σ_{i∈A_valid} p(i)
L_anchor = KL(冻结参照分布 || 当前分布)，两者使用相同问题与候选支持集。
```

各项损失先按有效样本和字段归一化，再按开发集与梯度量级设权重；不让 H×3 个坐标天然压过一个分类标签。位置按训练域尺度归一化，yaw 用周期损失；可对称夹爪的合法等价姿态按对称集合求最小误差。标签 mask 来源于记录与验真器，不来源于模型自己预测的 validity。

锚定是可选项，起步可设 λK=0。启用时，用已完成能力画像的冻结原生选项分布，或第一阶段已学会接口的冻结模型作参照；对齐候选顺序和支持集，不能把随机初始化 head 的分布当知识教师。无同义候选映射的样本不计算该项。

第一阶段冻结 VLM，训练 decoder／readout；第二阶段若确有证据表明表征不足，开放 rank 16 LoRA 与 head 联合训练。位姿与分类损失都可通过共享表征发挥作用；隔离连续梯度作为后续消融，不提前假设哪种更好。最小训练不必生成语言，原 LM 接口仅用于冻结能力画像与能力保持评估；需要时再加入原生回放锚定。

### 8.4 有限资源下的训练安排

<div class="my-6 max-w-full overflow-x-auto" role="region" aria-label="步骤对照表" tabIndex={0}>

| 步骤           | 实施起点                                                               | 继续或停止的依据                                                     |
| -------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 基座画像       | 原生工具／文本动作、冻结 typed 选择；当前图＋短历史                    | 目标指代与空间条件均失败时，先处理基座缺口，不盲目训练小 head        |
| 冻结接口学习   | 4–8k token；head LR 1e−4，AdamW，clip 1，有效 batch 32；先 50 步 pilot | 检查正确目标、单位、padding、缺失标签与分类—轨迹一致性               |
| 受约束适配     | 必要时 LoRA LR 1e−5，视觉塔先冻结；T/B/G 采样起点 60%/25%/15%          | 轨迹、条件理解和通用分类共同选择 checkpoint，不能只看机器人训练 loss |
| 训练域闭环修复 | 收集模型造成的偏差、夹空和恢复；只使用训练资产与任务                   | 若成功依赖 oracle 空间输入，返回视觉／数据环节，不直接上测试真机调参 |

</div>

默认资源上限仍为 16 × A100 80GB，先用 1–2 卡量测实际显存与吞吐；不为填满卡数预设训练量。先训练一条种子排错，主方法与关键对照再补 3 个训练 seed。比例、学习率和步数是可执行的起点，不是已验证最佳配置。64k、128k 与 10 Hz 均在核心迁移假设之后逐项验证。

### 8.5 几何信息与频率是实验条件

**G0** 输入多目 RGB、本体、身体描述与交互历史，不给相机内外参；**G1** 在此基础上加入静态标定；**G2** 再加入由 RGB 推断的空间 token。最小实验先比较 G0 与 G1，G2 后置。所有条件运行时都不读 RealSense 深度。G0 不能偷偷使用通过标定投影的坐标网格；G1 的静态标定属于设备配置，不是物体任务示范。

**G0 的难点是可观测性，而不只是模型规模。**任意未知相机下，单幅目标图像一般不能唯一确定机器人坐标中的米制位置。多目也需要跨视角与尺度线索；可见机械臂／已知工具尺寸、带实测位移的历史和训练中的相机变化可以提供这些线索，但不保证总能消除歧义。因此 G0 需单列“首帧、可见机器人”“有运动历史”“未见 rig”等条件；无法确定时允许补观察。G1 是判断失败是否来自空间映射的对照，而不是预先认定所有模型都必须标定。

训练和部署要对齐观测到启动的延迟：在仿真采集中随机化该延迟，并按计划实际启动后的时间网格取未来标签；延迟或状态偏移超出训练范围时废弃旧包并重新观察。离线记录若无法恢复执行时序，只用于不依赖精确延迟的辅助监督。

轨迹点间隔 0.1 s、模型重规划频率和 Sys0 控制频率是三个量。首先量测能稳定完成的 1–2 Hz 局部循环，按延迟选择执行前缀；之后再争取 10 Hz。若推理超过剩余路径时域，则保持已验证目标或暂停，不盲目延伸路径。真机始终记录墙钟时延和 t_obs、t_start，不能复制“推理时暂停仿真”的时间口径。

## 09 · 数据如何获取：从可控转移到可迁移监督

第一批数据推荐以可重置的桌面仿真为主：它能生成多视角 RGB、EEF 与夹爪轨迹，并验证语义变化后动作是否仍有效。公开机器人数据用于补充真实外观与运动经验，但不是把不同 action 数组直接拼起来。无论来源如何，学生输入与教师真值严格分开。

### 9.1 仿真采集：一条 episode 同时提供 T 与 B

1. **定义场景族并先划分。**例如训练／开发／测试分别采用 40／10／20 个不重叠资产家族；将同一 mesh 的缩放、纹理和改名视为同源。相机 rig、布局和指令组合另做留出。数量是先导预算，实际以可获得且合法使用的资产为准。
2. **采集有几何依据的教师行为。**在 LIBERO／robosuite 类环境上选择或构建抓取子任务，使用脚本、运动规划器或示范生成接近—对齐—闭合—提起—验证片段。教师可以读取仿真真值；学生只读按 G0/G1 声明的 RGB 与状态。[[52]](https://github.com/Lifelong-Robot-Learning/LIBERO/tree/8f1084e3132a39270c3a13ebe37270a43ece2a01)
3. **保存完整时序。**记录 RGB、view_id、时间戳、TCP／夹爪实测状态、请求控制、实际执行、相机与工具配置、任务条件和结果。保留控制延迟与跟踪误差，不能把请求动作直接当实际状态。
4. **构造 EEF 标签。**从验证有效的教师行为中取未来实测 TCP 状态，在目标时间网格重采样；旋转按合法旋转插值，夹爪开合事件单独保留。未来数据仅在 targets 域。发生失败后，从纠正行为重新取监督片段，不让失败轨迹伪装成成功轨迹。
5. **构造桥接判断。**用当前可见证据回答目标、空间约束、阶段和状态；成功／失败标签由未来结果验真，但提问必须区分“目前是否抓稳”和“继续会成功吗”。学生无法观测的当前事实标未知，不强制拟合特权状态。
6. **加入成对条件与恢复。**同场景换目标、换接近侧、加入禁区，再重规划／重执行得到标签。主动制造夹空、位置偏差、物体移动和视角缺失；保留原始失败及后续恢复。
7. **运行质量检查。**确认时间截止、单位、TCP、相机同步、轨迹可达性、事件顺序和分组隔离；抽查视频及 replay。原始失败率、标签来源和过滤比例一起记录。

起步采 1,000–3,000 条独立 episode，每条选取 10–30 个决策时刻；先验证覆盖再扩规模。同一条轨迹的 100 个窗口不等于 100 个独立环境。材质、背景、光照、相机、物体尺寸、夹爪几何、摩擦和控制延迟需要随机化，但随机化不能保证现实域被覆盖。

### 9.2 开源数据：按用途选择，而不是一次混入所有数据

<div class="my-6 max-w-full overflow-x-auto" role="region" aria-label="来源对照表" tabIndex={0}>

| 来源                                                                                                           | 采用方式                                                 | 必须补做的工作                                                                                    |
| -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| robomimic／MimicGen[[53]](https://robomimic.github.io/docs/datasets/overview.html)                             | 优先选择可回放、带状态的仿真片段；补采多目及失败         | 核对 action 的绝对／增量／关节含义；从可信状态或回放得到 EEF，而不是直接改字段名                  |
| DROID／OXE[[32]](https://droid-dataset.github.io/)[[31]](https://github.com/google-deepmind/open_x_embodiment) | 选择多视角 RGB、姿态、时间和夹爪信息足够的真实片段       | 按子数据集分别转换；缺失视角／姿态标 mask。逐项核查许可、来源与重复，不能宣称所有公开数据格式统一 |
| UMI[[30]](https://umi-gripper.github.io/)                                                                      | 真实工具运动、相对末端与夹爪经验的后续补充               | 处理相机位置、参考系、尺度、时间与工具几何；腕部视角不自动等价于固定多目                          |
| GraspNet[[54]](https://graspnet.net/)                                                                          | 仅作抓取几何辅助监督或候选上限诊断                       | 抓取姿态不是时间轨迹；原 RGB-D 数据中的深度不得变成 RGB-only 部署的隐藏依赖                       |
| 公开图文／文本分类及决策数据                                                                                   | 构建 G：指代、证据判断、约束理解、关系判断等动态选项问题 | 审查标签、许可与基准重叠；教师生成的答案是伪标签，需要验证，不视为事实真值                        |

</div>

明确区分 **S-sim**（只用仿真具身数据＋通用数据）和 **S-mix**（再加入其他机器人的公开真实数据）。两者都可以对目标非夕平台零样本，但只有前者能回答纯 sim-to-real 的问题。资源有限时先跑 S-sim；若视觉域差成为明确瓶颈，再引入经过筛选的 S-mix，而不是改变数据后继续沿用同一实验名称。

为了让第一轮数据可落地，B 从每个被选中的操作时刻生成 2–4 个可验真的问题，并按源 episode 与 T 一起划分；G 先整理约 2,000 条训练、500 条开发和 500 条留出问题，覆盖文本证据、图像指代、空间关系和约束组合。G 的源图像／文档必须先分组，再生成问法与候选，不能把同一源内容的不同改写分到训练和测试。这个规模只用于接口与混合训练 pilot，后续按覆盖缺口扩充。每条记录都带来源、许可、标签生成方式与验真状态；先选可追溯的小集合，比无法审计的大混合更容易解释结果。

### 9.3 三种输入路径如何进入数据

<div class="my-6 max-w-full overflow-x-auto" role="region" aria-label="输入路径对照表" tabIndex={0}>

| 输入路径              | 研究用途                               | 不允许的捷径                                                         |
| --------------------- | -------------------------------------- | -------------------------------------------------------------------- |
| 多目多物体框 → EEF    | 便宜的空间／历史诊断与表示上限分析     | 框中心通常不是同一三维点；不能从 bbox 直接假定深度、接触点与抓取姿态 |
| 多目 RGB → EEF        | 最小真机模型主线，保留形状与外观细节   | 不在输入里提供仿真目标位姿、未来框或执行答案                         |
| RGB → 框／掩码 → EEF  | 显式瓶颈对照，定位感知和表示损失       | 区分 GT 框与预测框；部署检测器误差需进入训练和评估                   |
| RGB＋可选空间块 → EEF | 信息融合扩展；框可作为辅助而不丢弃原图 | 比较时记录增加了哪些信息，不把额外传感证据归为网络结构收益           |

</div>

## 10 · 仿真测试：先证明动作真的受理解支配

仿真分两层。第一层是离线受控问题：分类、同场景改口和数值接口是否正确。第二层是闭环 rollout：模型是否能在自身动作造成的新状态中继续完成抓取。离线轨迹误差下降不替代闭环成功。

### 10.1 主要对照组

<div class="my-6 max-w-full overflow-x-auto" role="region" aria-label="组别对照表" tabIndex={0}>

| 组别                 | 定义                                       | 检验什么                                          |
| -------------------- | ------------------------------------------ | ------------------------------------------------- |
| O：Oracle＋固定 Sys0 | 可核验目标／教师计划交相同执行器           | 环境与执行器上限；不作为模型 zero-shot 成绩       |
| N：原生基座          | 同一 VLM 用原生文本／工具接口给 EEF        | 基座已具备的能力与 typed 接口损失                 |
| T：轨迹训练          | 同骨干和轨迹读出，用轨迹及基础执行状态监督 | 常规动作专业化基线                                |
| T＋G                 | 加入其他场景分类，不加入操作判断配对       | 通用回放本身能提供多少帮助                        |
| T＋B＋G              | 完整最小方法                               | 操作相关判断与跨任务配对是否进入动作              |
| 关键消融             | 去历史、打乱 B 标签、冻结与 LoRA、G0 与 G1 | 排除数据量、辅助 loss、历史伪相关和几何信息的影响 |

</div>

主比较保持相同机器人 episode 曝光量、骨干、动作表示与执行器，并报告混合数据增加的计算；再做固定总 token／训练算力的补充对照。两种口径不能混用，也不能在增加数据后把收益全归于新 head。第一轮只跑 T、T＋G、T＋B＋G 和 O；N 与 Astra 可先在固定小子集评估，资源允许再扩大。

### 10.2 留出条件

<div class="my-6 max-w-full overflow-x-auto" role="region" aria-label="测试层对照表" tabIndex={0}>

| 测试层         | 保持／改变什么                             | 指标                                               |
| -------------- | ------------------------------------------ | -------------------------------------------------- |
| 已知分布       | 新 episode，训练内资产与条件范围           | 接口、抓取成功、跟踪误差；只说明基本可学习性       |
| 新资产与布局   | 留出 mesh 家族、外观和物体组合             | 抓对物体、提起保持、碰撞／不可达率                 |
| 新语义组合     | 词汇已见，目标×关系×接近要求组合未见       | 成对条件正确率、约束满足率、语言替换后的轨迹正确性 |
| 相机与执行迁移 | 未见 rig、缺视角、延迟、控制增益和夹爪几何 | G0/G1 分项，首次动作与纠正后的成绩                 |
| 失败与历史     | 夹空、目标移动、未到位；比较有／无真实历史 | 恢复成功、错误继续率、观察／升级的精确率与覆盖率   |

</div>

先导可按 5 类条件 × 20 个独立场景 × 4 个指令／扰动条件组织约 400 次 rollout／模型；同场景四条不是独立样本，统计按场景聚类。测试清单提前固定，全部失败与拒绝计入。主方法和关键基线至少 3 个训练 seed；评估随机 seed 不能替代训练 seed。

### 10.3 判定知识进入动作，而非只保留分类

必须同时看三项：G 的未见分类成绩是否保持；B 在未见操作条件下是否正确；对应轨迹是否满足同一条件并完成任务。对“抓杯子／抓碗”的成对测试，两条都正确才算通过，不以轨迹变化幅度代替正确性。无关措辞改写则应保持任务结果，不要求输出逐点完全相同。

如果 T＋G 保住分类却不改善动作，而 T＋B＋G 改善，则支持桥接数据的作用；如果三者相同，就没有证据说明 mixed classification 对轨迹有帮助。如果只在提供真值 3D 的条件下改善，则结论局限于空间读出，尚未证明视觉策略。

仿真通过后仍不能推定真机成功。还要用固定模型在未见相机、材质和执行条件上压力测试，并把已知域差带入真实测试设计。建议将“ID 基本抓取达到约 80%、关键语义／历史对照出现正向结果”作为进入真机的开发门槛起点；阈值在开发集锁定，并非普适成功标准。

## 11 · 真机测试：在非夕＋多目 RGB 上检验零样本

目标平台是非夕机械臂、夹爪与多个 RealSense 的 RGB 图像，**不使用深度通道**。第一轮按平行夹爪俯抓设计，具体机械臂型号、夹爪行程、TCP 与 RDK 版本在接入时核对。设备初始化需要控制模式、坐标约定和实际反馈接口，不能仅凭品牌名推断。

### 11.1 零样本究竟指什么

<div class="my-6 max-w-full overflow-x-auto" role="region" aria-label="允许对照表" tabIndex={0}>

| 允许                                                                         | 主测试中不允许                                                       | 必须单列的情况                                           |
| ---------------------------------------------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------- |
| 仿真／其他机器人训练；固定 TCP 与夹爪配置；空工作区控制验证；G1 静态相机标定 | 用目标真机测试任务／物体轨迹训练、调 prompt、定阈值或选择 checkpoint | S-sim 与 S-mix；G0 与 G1；用目标真机任务调参后的适配系统 |
| 当次 episode 的实际动作与结果作为历史                                        | 提供目标任务成功示范；从之前测试 episode 带入物体专属攻略            | 带示范 ICL、跨 episode 记忆、额外探测初始化              |

</div>

第一轮训练过“抓取”技能，所以主要结论是**未见真实实例／场景与条件组合上的 zero-shot transfer**，不是“从未学习抓取却突然会抓”。如仿真包含非夕 URDF 或能力描述，则可说没有目标真机任务数据，不能说完全未知本体。基础模型预训练可能见过类似物体，应如实记录这一限制。

### 11.2 先固定执行器，再冻结整套测试条件

用规则控制和已知空中目标检查 TCP、轴方向、时间、夹爪开合与回执，不通过这些测试学习目标抓取策略。Sys0 对所有比较组保持相同版本，执行相同插值、限幅与拒绝规则；不得只替某个模型修正目标。复杂重规划器若加入，应作为单独辅助条件。非夕 RDK 提供实时与非实时接口，具体调用与频率依实际设备核对。[[55]](https://github.com/FlexivRobotics/flexiv_rdk)

冻结模型权重、prompt、上下文打包、相机处理、归一化、阈值、schema、Sys0 及预算。正式开始后遇到问题只记录，不调整后继续沿用同一 zero-shot 分数；修复后应以新版本重新评测预登记清单。

### 11.3 测试清单与成功定义

先导测试采用 30 个未进入训练／开发的真实物体 × 3 个布局 × 2 个指令条件，共 180 个条件／系统。包括简单属性指代、关系指代和一项接近约束；选能由当前夹爪俯抓的刚体，并公开纳入／排除规则。透明、软物、复杂把手、密集遮挡另列挑战集，不混进第一轮技能定义。

- 意图正确：选对物体，满足有效指令和禁区要求。
- 真正抓起：正确物体离桌 ≥5 cm，保持 ≥2 s；放置成功另计。
- 可恢复：分别报告首次尝试与最多一次重试的成功率。
- 代价明确：超时、拒绝、碰撞、观察次数、总耗时与端到端延迟。

5 cm／2 s、重试与时限是预登记起点，需在测试前固定。成功由独立视频判定／人工盲评及可用实测信号核验，不能由 Sys1 自报完成来评分。每次 reset，随机模型执行顺序；按物体／布局聚类计算置信区间，而不是把每帧当独立样本。

### 11.4 与 GPT‑6 Astra 怎么公平比较

Astra 是最终外部参照，必须在同一台非夕和同一测试清单上实测，不能移植网络演示的成功率。给它与 Sys1 相同的 RGB、本体、几何条件、有效指令、历史额度、动作接口与执行器；记录确切模型快照、reasoning 设置、工具和调用预算。Astra 可以通过原生工具／文本接口输出数字，学生直接通过 head 输出，格式错误与拒绝都计入端到端结果。

分开两条比较：**能力赛道**给相同动作／观察预算并放宽统一墙钟上限；**部署赛道**给相同墙钟时限，计入推理等待。Direct 与 Agentic Astra 分组报告；若增加工具、更多观察或在线 Sys2 帮助，就不能仍叫同条件的独立策略对照。

受预算限制，真机核心组先保留 T＋B＋G、T 和 Astra，其他消融在仿真完成；如预算仍不足，先做 60 条条件 pilot，不宣称“达到 Astra”。若要正式声称接近 Astra，可预先约定配对成功率差的置信下界高于 −5 个百分点，并根据 pilot 方差估计样本量。180 条未必足够证明非劣；“没有显著差异”不等于等效。

G0 还要报告第一次动作、积累交互后和新相机 rig 的结果。如果系统先靠一轮探测摸清视觉—动作关系，应单列在线系统辨识的成本，不把它隐藏为无成本零样本。

## 12 · 实施顺序、已有基础与最终判断

研究按证据推进。当前最应投入的是统一多目 RGB 记录、可回放的 EEF 教师数据和混合任务训练入口；不是继续扩充任务清单，也不是先投入长上下文或复杂概率解码。

### 不同结果对应不同下一步

<div class="my-6 max-w-full overflow-x-auto" role="region" aria-label="观察到的结果对照表" tabIndex={0}>

| 观察到的结果                           | 说明什么                           | 下一步                                                |
| -------------------------------------- | ---------------------------------- | ----------------------------------------------------- |
| Oracle 也失败                          | 执行接口、数据或任务本身有问题     | 先修 TCP、状态恢复、控制器与验真                      |
| 分类正确，动作不响应                   | 语义没有进入轨迹，或两任务表征割裂 | 增加正确配对、检查共享层与条件读出，不能只加无关分类  |
| 原生基座会，typed head 不会            | 新接口未读出原有能力               | 调整问题查询与监督，必要时受约束适配                  |
| 仿真好，真实视觉差                     | 存在感知／相机域差                 | 先查 RGB 与时间处理，再比较 G1 或 S-mix；修订结果单列 |
| 目标正确但抓不住                       | TCP、接触、夹爪或局部几何仍不足    | 分开计划与实际轨迹，补足可验证的交互数据              |

</div>

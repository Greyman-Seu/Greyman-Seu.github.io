从观测到动作：
操作空间的完整构想与最小子集

我们希望找到一种共同表示，既能支持不同的机器人操作，又能让「观测 → 空间」和「空间 → 动作」两端的数据更容易获得。

01 · 我们构思的全集这个空间是什么，包含什么，怎样支持各类操作，数据从哪里来。02 · 一个最小子集图像与 bbox 状态对齐、合成状态训练动作：它与全集的关系，以及可行的条件。

“全集”指当前讨论希望覆盖的完整框架，不代表已证明能覆盖所有操作。文中的表示和训练设计均是候选构想。

第一节 / 完整构想

我们想要的操作空间，是什么样的？

先把目标结构说清楚。bbox 只是后面用来实例化其中一部分的方式。

1.1 一句话定义

一个带有空间位置和时间关系、由多种信息共同监督学习的操作表示。它要让模型读到：世界与身体现在怎样，刚刚发生了什么，以及当前操作需要哪些局部细节。

文字、图像、数值和记忆组成的 query 告诉模型“希望怎样改变”；操作模型结合这个空间与当前本体，快速决定下一步动作。

可以把它理解成一张可持续更新、可读取局部信息的操作地图。地图上有物体和身体的位置；每个相关位置还能关联外观、运动和接触等特征。它既不是一张完整重建的三维照片，也不要求人工为每一维特征命名。

人工约定：信息如何对应

坐标、尺度、时间、对象与身体

不同相机、表面局部、身体部位和传感器记录，需要有稳定的空间与时间对应关系。先做标定、去畸变和坐标统一，尽量减少观测器差异。

模型学习：哪些信息值得保留

由几何、外观、运动、交互共同约束

模型内部特征不必是一张人工属性表。用不同输入、叠加不同任务的对比学习，让各自只覆盖部分信息的数据共同约束表示，不要求每份数据都有完备标注。

与 BEV 的相似处，是先给信息一个空间组织方式，再学习其中的特征。操作的区别在于：对象可移动、变形，被身体接触；局部表面和过程状态也可能决定动作。因此目前不把它限定为单一平面网格。BEVFormer 的空间查询与学习特征

是否一定需要这个抽象层？还没有定论。设计它的理由，是希望复用非机器人视觉数据和合成动作数据。若建立、标注与迁移这个空间的总成本并不更低，直接从观测学习动作仍然是合理选择。显式空间也可以参与端到端联合训练。

1.2 全集要容纳哪些信息？

这里的“全集”是一套表达能力要求，不是要求每条样本填满所有字段。建议采用“世界与局部特征＋身体＋交互历史”的组织方式，任务 query 单独输入。

组成 需要表达什么 为什么操作需要它
世界与局部几何 物体、部件、周围空间的位置与关系；需要时读取局部表面和形变。 知道往哪里接近，哪里可以通过，哪些局部需要对齐。
外观与属性 类别、颜色、纹理、图案；与位置关联的图像细节。材料等属性可以由标签或交互经验监督。 找对目标；区分污渍、笔迹和物体局部。摩擦、软硬等差异也会影响动作效果。
本体 身体结构、当前构形、关节与末端状态、动作接口和可执行范围。 相同操作目标，需要通过不同身体实现；不能只有世界，没有“谁来操作”。
交互与接触 握持、支撑、固定、滑动等关系；可获得的触觉、力觉及其时空对应。 区分“碰到了”“抓稳了”“正在滑落”，支持细致调整和停止。
短时历史与变化 最近的观测、已执行动作、物体运动和反馈，保留顺序与对应关系。 判断动作有没有生效，当前处于哪个阶段，是否需要修正或恢复。
任务 query
（空间的使用条件）		 目标与过程要求，可用文本、图片、位置、数值、参考轨迹表达；上层也可加入相关记忆或他者指令。 同一个世界，可以要求拿起、放下、擦拭或描画。状态本身不唯一决定动作。

具体可以怎样承载？一个候选是：用较粗的三维结构组织场景，以对象／部件和局部表面位置作为“信息挂载点”；挂载可学习特征及原图对应关系，再关联身体与时间记录。物体变形时，局部位置和关联也要更新。它可以有多个尺度，不必把所有信息压进一个全局向量。

世界理解可以粗，末端交互需要细。不要求把全世界重建到毫米级。精细接触定位主要依靠末端触觉、力觉等反馈不断校正。与此同时，绘画、擦拭等任务仍需读取足够细的视觉信息；几何重建粗略，不等于把所有外观也压粗。

历史有两种用途：上层将长期／短期记忆组织进 query；末端保留近期感知—动作反馈以支持闭环操作。两者可以关联，不要求末端承担长程记忆组织。

1.3 这个空间怎样被模型使用？

上层 query：文字／图像／数值／记忆 → 指定目标、局部对象和过程要求 → 交给操作模型
观测与身体反馈图像、深度、身体状态
触觉／力觉、近期动作
→
共同操作空间 Z有空间与时间对应的特征
支持整体理解、局部读取
→
操作模型结合 query 与当前本体
生成下一步／短片段 action
执行动作 → 获取新的观测与接触反馈 → 更新空间 → 再决策

决策输出可以考虑低频更新的 EEF 位置、姿态与轨迹，便于跨本体复用人类和 UMI 数据中的操作经验；下层则结合高频反馈完成实际交互。

这个接口要支持四件事：更新状态、按 query 读取信息、预测短时操作效果、生成动作。“预测效果”可以作为训练约束或短时决策能力，不要求每一步都先生成完整未来场景。

三个期待 对完整系统的要求
操作泛化 换场景、物品或身体后，仍能利用共同信息完成目标。明确保留本体差异，让共享的是操作能力，而非强行共用同一组关节指令。
操作安全 初期准确率可以有限，但试错不能依赖破坏自己或物品。需要约束、接触反馈、停止与恢复能力；空间表示本身不能保证安全。
闪念决策 上层负责丰富 query 的组织，末端快速读取、决策与反馈。灵巧手末端约 100 Hz 是当前设计期待，具体是否由同一个模型承担，需要结合时延和控制架构确定。

1.4 为什么它需要覆盖这些信息？用操作任务来检查

不同任务读取同一框架中的不同部分。判断“全集是否够用”，要看它能否保留每类任务中会改变正确动作的信息。

拉开抽屉

query
把抽屉拉开 10 cm，保持平稳。
读取空间
把手位置、抽屉运动方向、手的位置，以及握持和受力反馈。
期望变化
手与把手建立稳定关系，抽屉沿允许方向移动到目标位置。
缺少会怎样
只知道抽屉整体外框，不一定知道抓哪里；只看单帧，也难以判断刚才是否拉动。

绘画只是检验“外观与目标变化能否表达”的一个场景。全集同时面向裸手、手物和工具操作。

1.5 全集的数据怎样获得？

底层设想是拆开两类昂贵程度不同的数据：先用较容易获得的视觉、几何和变化数据学习空间，再用合成执行学习空间到动作。不同来源可以只监督空间的一部分，不需要每条真实数据都带机器人动作标签。

要学的内容 数据与标签来源 仍然存在的成本
位置与结构 真实多目／RGB-D 配合标定，生成几何与对象对应；仿真直接导出深度、对象和部件标签。 采集同步、标定、遮挡处理；检测与跟踪结果需抽检纠错。
外观与语义 图像、局部图像对应、类别与描述；渲染可生成颜色、纹理、光照变化。 描述与局部对应需质量检查；视觉教师特征不等于人工真值。
运动与变化 人类／物体视频配合跟踪与深度，或仿真逐帧状态。 真实视频的遮挡、形变和对应误差；仅有运动不等于知道机器人应下发什么指令。
接触与物理响应 仿真接触与执行记录；真实端有传感器时，采集对应的触觉／力觉。 普通视频没有准确力标签；仿真的材料、摩擦和柔性行为存在误差。
本体与动作效果 本体模型、控制接口；在仿真中由规划器、控制器、强化学习或示范产生动作，记录结果。 资产和物理设置、有效策略、失败筛选，以及向真机迁移的验证。
“数据容易收集”是这个空间要验证的价值，不是已有结论。几何与外观标签通常更容易自动产生；接触、柔性和有效动作不会因换了表示就自动变便宜。比较时应算上资产制作、标注纠错、仿真策略和迁移的总成本。
补充：GS、体素、UV、CAD、Blender、USD 放在哪里？

它们分别提供表示或数据制作的一部分，不能单独替代完整操作空间：

  • GS：可作为外观与几何的重建来源，但重建结果本身没有定义身体、接触和动作效果。
  • 体素／点云／表面采样：可承载空间位置与局部特征；分辨率、空区域和局部细节之间需要取舍。
  • UV／贴图：把外观关联到表面，适合保存图案与颜色；单独不能描述交互历史。
  • CAD：提供已知物体／本体的几何和结构信息，不要求所有真实物体都先做成 CAD。
  • Blender／USD：用于资产、场景、属性组织和数据生成／交换。统一文件格式，不等于模型内部特征已统一；USD 本身不是物理模拟器。

当前构想倾向于吸收这些表示能提供的监督，再学习共同特征。尚未选定唯一的底层几何载体。相关文档：Blender 属性、Open CASCADE、USD Physics。

全集的核心构想：以空间和时间组织世界、身体与交互信息，通过多种监督学习共同特征；上层用丰富 query 指定目标，下层读取这个空间快速行动。

尚待确定的是具体载体、需要保留的最小信息、不同监督如何融合，以及相较直接端到端是否确实节省数据。下一节只分析其中一个受限实例。

第二节 / 一个最小子集

用多目 bbox 对齐图像，再用合成状态学习动作

这是对完整构想的一个简化版本。它主要探索：不依赖真实机器人动作示范，能否把合成状态上学到的操作能力交给视觉模型使用？

2.1 它与全集的关系：保留架构，压缩状态内容

最小子集的设想：对「图像＋操作 prompt」和「多目 bbox＋一些描述」做对比学习，再生成大量「合成状态＋action」数据。极端情况下，不用真实机器人训练数据，也希望得到一定泛化。

它保留了全集中的两条连接：观测与状态相互对应，状态与动作相互对应。简化的部分是状态内容：先用框、描述和简单目标代替完整的局部几何、外观、接触与历史。

全集中的信息 一个最小子集如何表达 压缩之后的边界
世界与局部几何 多目 bbox、对象对应、必要的相机参数。 表达粗位置与范围；整体框不直接给出把手、布料层叠或精细形状。
外观与属性 类别、颜色等简单描述；图像侧仍可看到外观。 状态侧没表达的纹理与局部差异，不会自动成为动作模型可用的信息。
本体 这一设想未展开。若固定机器人，可固定身体结构；控制仍需当前身体状态或等价反馈。 固定本体可以简化问题；单靠物体 bbox，不能知道手现在在哪里、下一步怎样动。
交互与历史 可先限制为简单操作；若描述中加入阶段或关系，就显式增加对应信息。 省略接触与历史后，对滑动、受阻、恢复、柔性操作的表达能力有限。
任务 query 操作 prompt，必要时包含目标位置或数值。 先覆盖有限目标类型；丰富图像 query 和复杂过程约束属于全集的更大范围。
最小子集是在检验连接方式，不是在宣称 bbox 足以表达一切。如果它成功，说明某些任务可以通过共同表示复用合成动作数据；它不能单独证明全集已成立。

2.2 三段流程：对齐 → 学动作 → 部署

1

对齐：让同一场景的图像和状态表达对应起来

图像 I ＋ prompt → 图像编码器 → Zᵢ
多目 bbox ＋描述＋ prompt → 状态编码器 → Zₛ
匹配场景拉近；同任务下的不同状态要能区分。

配对图像可以来自仿真渲染，也可以来自不含机器人动作标签的真实视觉采集。若两侧都输入 prompt，需要防止模型只靠相同文字完成匹配。

2

学动作：在合成状态上学习怎样完成目标

合成状态 S → 状态编码器 → Zₛ
Zₛ ＋任务＋身体状态 → 动作模型 → action

让机器人在仿真中实际执行，记录状态、动作和结果。数据量可以更多集中在状态轨迹上，不必每一条都渲染图像。身体与任务的条件必须与动作对应。

3

部署：换成图像侧输入，调用同一份动作能力

真实图像＋任务 → 图像编码器 → Zᵢ
Zᵢ ＋任务＋身体反馈 → 动作模型 → action → 再观测

关键假设是：对于相同操作，Zᵢ 能替代 Zₛ 被策略使用。对比学习让两者相似，但还不足以保证这种替代对动作有效。

以上是逻辑上的三个环节，不要求训练时严格分三次。这里保留这个架构设想，再单独分析它成立的条件。

2.3 数据具体长什么样？“假的 bbox＋action”怎么生成？

需要两种样本。第一种建立视觉接口，第二种建立动作能力。以下是结构示例，省略真实数值，避免把示意记录误作可执行轨迹。

A · 图像—状态配对

同一时刻、同一场景的两种表达

图像：相机 A、B 的同步画面
相机：内参、外参
对象 7：A 视角 bbox；B 视角 bbox
描述：红色方块，在托盘左侧
prompt：将红色方块放到托盘中央
对应：对象 ID、时间戳

仿真中从同一场景同时渲染与导出标签。真实端可用检测、跟踪和人工抽检制作，不需要为这条样本录制机器人动作。

B · 状态—动作—结果

让动作具有实际执行依据

当前状态：bbox＋描述 Sₜ
任务：同一操作 prompt
身体：关节／末端当前状态 bₜ
动作：实际下发的控制指令 aₜ
结果：下一状态 Sₜ₊₁
记录：成功／失败、接触等反馈

action 可以是末端增量或关节目标等，必须注明坐标系、单位和控制周期。额外结果标签可用于训练，不必全部变成部署输入。

一致的三维场景 → 投影出多目 bbox → 由控制器／规划器／策略生成 action → 在仿真执行 → 保存状态、动作与结果

“合成”应是从一个一致的世界生成数据。分别随机造几个相机框，再随机配一个 action，通常无法保证多目一致、身体可达或动作有效。

数据制作时需要明确的约定
  • 框的含义：可见部分的框，还是完整物体投影框？跨视角对象 ID、相机参数与时间必须一致。多目框约束位置，但不自动等于完整三维形状。
  • 动作来源：简单任务可由规划与控制规则生成；复杂操作仍需有效的策略学习或示范。自动记录 action，不代表自动获得正确 action。
  • 成功与失败：成功轨迹可用于模仿；失败轨迹可帮助学效果与恢复，不能不加区分地当作正确示范。
  • 部署能拿到什么：仿真内部完整状态可用于奖励、教师或监督；实际策略的输入要与真实可获得的观测匹配。
  • 图像覆盖：大量动作轨迹可以不渲染，但图像—状态配对仍要覆盖动作模型遇到的状态变化，不能只对齐少量静态场景。

2.4 可行性：有希望，但要跨过三道具体门槛

门槛 最小子集面临的问题 可考虑的约束或边界
① 状态足够用 框和描述相同，是否仍可能需要不同动作？例如抽屉整体框相同，把手却在左侧或右侧。 限制任务与形状，或补入局部框、方向、部件描述。若关键差异完全缺失，增加样本数量无法恢复它。
② 两侧真的可替换 图像和状态特征接近，不代表策略会输出同样合适的动作；细小位置误差也可能改变抓取点。 同 prompt 的难负样本、局部空间监督，以及配对场景的动作／效果一致性。需要让对齐服务于操作。
③ 合成经验能迁移 真实图像可能落不到正确表示；真实摩擦、延迟、柔性等又可能使动作失效。 分别处理视觉差异与物理差异，匹配可观测输入和控制接口，并依靠闭环反馈。对齐不能单独解决两者。
较有希望的范围

受限形状与明确目标的操作

固定或已知本体，规则刚体，有限抓取方式，简单搬运与摆放。位置、尺寸、排列、颜色等变化可以构成有意义的泛化维度。

不能直接推出的范围

复杂接触、柔性与外观精细操作

叠衣服、灵巧工具操作、细致描画等，通常依赖简化状态没有保留的信息。跨本体泛化也需要身体表达与相应训练覆盖。

bbox 做“硬瓶颈”和做“辅助监督”，有什么区别？

硬瓶颈：图像先转换为框和描述，再预测动作。没被写进状态的信息无法继续传递。

辅助监督：图像编码成更丰富的特征，bbox 只负责约束其中一部分。这样可以保留更多外观信息，但若动作模型仅在 bbox 状态上训练，它不会自动学会使用图像侧额外的特征。

因此，从最小子集连接到全集，需要让新增的局部几何、外观、接触与历史信息也获得操作意义；不是只扩大特征维度。

2.5 “不用真机数据”能成立到什么程度？

设定 含义 判断
零真机动作示范 可用真实图像、人类视频和视觉预训练；不使用真实机器人动作标签。 这个架构具有合理动机；特定任务已有相关迁移证据。仍需验证状态是否充分、策略是否可迁移。
零目标本体训练数据 可用其他来源的数据；目标机器人只用于部署与评估。 要求进一步匹配本体和控制接口。不能由视觉—状态对齐自动推出。
完全合成训练 连真实视觉预训练也不用。 约束最强。特定视觉定位及抓取应用有先例，但通用操作不能据此下结论。

这里“零数据”指训练限制；部署读取真实传感器、必要标定和真实执行评估，仍然是系统的一部分。

对最小子集的判断：在适当受限的任务中值得成立为一个研究假设。真正要检验的是：能否用易获得的图像—状态配对，把合成状态上的动作能力迁移到真实视觉输入。

对全集的意义：它验证“共同空间连接两端数据”的机制；全集还要容纳局部几何、外观、身体、接触与历史，并让这些信息也能参与动作学习。最小子集成功是局部证据，失败也需要区分是 bbox 信息不足、对齐不够，还是仿真迁移失败。

补充依据：合成迁移、视频预训练与本体迁移
Domain Randomization（2017）

仅用随机化合成图像训练定位模型并用于真实抓取，未依赖真实图像预训练。支持合成视觉训练的可能性，不能外推为通用操作策略已解决。

DexPoint

通过点云、身体信息和仿真策略学习，实现特定灵巧操作的真实迁移。支持共同输入与合成动作学习路线；不是 bbox 足够覆盖全部任务的证据。

LAPA

从无动作标签的视频学习潜在动作，再用机器人动作数据适配。支持便宜视频用于预训练，不证明后续完全无需动作适配。

Object-centric 3D Motion Field

利用仿真训练的运动估计器，从人类 RGB-D 演示提取三维运动并用于机器人控制。为全集中的变化监督提供参考，仍有遮挡、灵巧手和柔性扩展限制。

DexMachina

利用人类示范的物体状态、运动与接触线索，在仿真中学习不同灵巧手实现操作效果。支持本体与效果表达的思路，主要证据来自仿真。

这些工作验证的是不同片段，尚不能拼成“完整通用空间已经成立”的结论。
